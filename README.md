# darb — Cross-Layer Cloud Attack-Path Analyzer

darb (درب) is Arabic for path or trail.

darb reads Kubernetes and AWS as **one graph** and finds the paths from an
attacker's entry point (an exposed or compromised pod) to crown-jewel data (S3
buckets, KMS-protected data, Secrets Manager secrets, SSM SecureString
parameters, Kubernetes Secrets). Every hop carries its evidence (`file:line` or
ARN), every path its **cheapest fix** (a weighted minimum cut), and
`darb remediate` proposes a patch that is verified twice before it is shown.

Principles: no number without evidence; anything that cannot be evaluated is
**UNKNOWN**, never safe; scanning is read-only and never modifies your files.

> **Status: under development, before 1.0.** One pre-release is published,
> [v0.1.0-rc.1](https://github.com/r3oof-900/darb/releases/tag/v0.1.0-rc.1).
> Not yet tested against a real AWS account or cluster: only fixtures, fakes,
> LocalStack and kind. The bundled AWS managed-policy snapshot holds every AWS
> managed policy at its default version as of 2026-11-23 (1622 policies); one
> published later is reported as UNKNOWN until the snapshot is refreshed. Read
> [Known limits](#known-limits) before trusting a scan of a real account.

## Install

From a [release](https://github.com/r3oof-900/darb/releases) (Linux, macOS,
Windows; amd64 and arm64). Each release has a `checksums.txt` signed
keylessly with cosign, an SPDX SBOM per archive, and build provenance for
every file:

```sh
cosign verify-blob checksums.txt \
  --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github.com/r3oof-900/darb/.github/workflows/release.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
sha256sum --ignore-missing -c checksums.txt
gh attestation verify darb_0.1.0-rc.1_linux_amd64.tar.gz --repo r3oof-900/darb --signer-workflow r3oof-900/darb/.github/workflows/release.yml
```

From source (Go 1.26 or newer):

```sh
go install github.com/r3oof-900/darb/cmd/darb@latest
```

## Quick start

Scan Terraform and Kubernetes manifests together (`darb.yaml` in the root
names the account, region and cluster; see
[tests/fixtures/01_classic/vulnerable](tests/fixtures/01_classic/vulnerable)):

```sh
darb scan tests/fixtures/01_classic/vulnerable
```

A path is enough: darb finds the Terraform directories, Kubernetes manifests
and snapshots under it, and reads its `darb.yaml`. The same scan with explicit
flags is `darb scan --root tests/fixtures/01_classic/vulnerable --terraform terraform --k8s k8s`.

Real output (abridged):


Then:

```sh
darb remediate --root ... --terraform terraform --k8s k8s b2113156   # plan, both verifications, the patch
darb remediate ... --write b2113156                                   # apply a verified narrow fix (clean git tree)
darb scan ... --format html --output report.html --fixes              # self-contained report with verified fixes
darb explain ... b2113156                                             # the finding in plain words
```

## Inputs

| Input | Flag |
|---|---|
| Terraform, static (HCL) | `--terraform DIR` |
| Terraform plan (JSON or binary) | `--plan FILE[=TFDIR]` |
| Kubernetes manifests | `--k8s DIR[=CLUSTER]` |
| AWS offline snapshot | `--aws-snapshot DIR` (written by `darb collect-snapshot --out DIR`) |
| AWS live, read-only | `--live-aws` with `--aws-profile`, `--aws-region`, `--aws-assume-role` ([permissions](docs/PERMISSIONS.md)) |
| Kubernetes live, read-only | `--live-k8s CONTEXT[=CLUSTER]`, `--k8s-eks NAME`, `--kubeconfig` |

## Commands

| Command | What it does |
|---|---|
| `scan` | the analysis; `--format console\|json\|sarif\|html\|markdown\|junit`, `--fail-on`, `--ignore`, `--baseline`, `--fixes`, `--timestamps`, `--llm` |
| `remediate FINGERPRINT` | the fix of one finding: plan, in-memory and on-file verification, patch; `--write [--allow-revoke] [--force]` |
| `explain FINGERPRINT` | one finding in plain words (template text, or an LLM with `--llm`) |
| `collect-snapshot --out DIR` | live AWS collection into an offline bundle |
| `rules list`, `rules show ID` | the rule catalog with rationale, ATT&CK techniques and references |
| `graph` | the whole access graph of the inputs, as Graphviz DOT or JSON |
| `doctor` | what is installed and configured; `--probe-aws` / `--probe-k8s` to test access |
| `version` | tool version, commit and rule-catalog version |

Global flags, accepted anywhere on the command line: `--log-format text|json`
(logs on standard error, every record through the secret redactor; the report
on standard output is unchanged) and `--debug` (info and debug records, and the
stack trace of an internal error). Without `--debug` only warnings are logged.

`--format markdown` is a summary for a pull request comment (at most 60000
bytes; the rest is counted in a "more findings" line); `--format junit` makes
each finding a test case, failing at or above `--fail-on`.

Exit codes: 0 clean (and coverage complete), 1 findings at or above
`--fail-on`, 2 usage or configuration error, 3 incomplete scan, 4 internal
error. Precedence 4 > 2 > 1 > 3 > 0.

## Optional LLM explanations

Off by default. `--llm anthropic` (key in `ANTHROPIC_API_KEY`, never a flag)
adds a plain-words explanation to each attack path and an executive summary.
The provider gets structured fields of the report only, with every secret
redacted; `--llm-redact-identifiers` also replaces account IDs, ARNs and names
by tokens restored locally. It never changes a verdict, a score or a fix, and
every explanation is labelled "AI-generated explanation". Details:
[DESIGN.md §10](docs/DESIGN.md#10-llm-integration-phase-7),
[THREAT_MODEL.md](docs/THREAT_MODEL.md).

## Known limits

Recorded in [DESIGN.md §12.1](docs/DESIGN.md#121-known-constraints-carried-between-phases).
The most important before a real scan:

- **AWS managed policies**: the bundled snapshot is IAM's list of 2026-11-23
  (1622 policies, each at its default version). A policy published or
  changed later is not in it: an attached one is UNKNOWN (reported, never
  treated as "no permissions") until `tools/refresh-managed-policies` runs
  again; a changed one is read at its 2026-11-23 version.
- AWS RAM shares of advanced SSM parameters are not collected: a parameter
  shared only through RAM is not seen as shared. The report names every
  parameter of the input that can be shared (a `not-modelled` note).
- **KMS grants and S3 object ACLs can still hide a real path where darb cannot
  see them.** Grants are collected (`kms:ListGrants`, `aws_kms_grant`) and
  evaluated; what is left: grants AWS services create at runtime, which a
  Terraform scan cannot see, and keys whose grants could not be listed. A
  bucket ACL only lists objects, so it is never a read; object ACLs can grant
  read to anyone or another account, and darb does not read them: a bucket with
  ACLs enabled (or not known to be disabled) gets a coverage gap. The report
  names those keys and buckets in `not-modelled` notes.
- AWS Organizations SCPs and RCPs are not collected: they only restrict access,
  so without them darb may report a path that one of them blocks, never hide
  one (a `not-modelled` note on every scan with AWS data).
- Every limit and how the report states it: [DESIGN.md §12.3](docs/DESIGN.md#123-limits-every-report-states-phase-7).

## Development

Requires Go 1.26 or newer and [Task](https://taskfile.dev).

```sh
task tools    # install pinned golangci-lint, task, lefthook, govulncheck, gitleaks
lefthook install
task ci       # vet, lint, race tests, govulncheck, fixture check
```

`-race` needs cgo and a C toolchain. On a machine without one, `task test:norace`
runs the tests without it; CI always runs with `-race`.

The package dependency rules live in `internal/archtest/layers.go`. After
changing them run `task gen`, which regenerates the depguard rules in
`.golangci.yml` and the table in `docs/DESIGN.md`. New dependencies must be at
least two weeks old (`go run ./tools/depage`).

The scenario 13 fixture uses a real Terraform plan. Regenerating it needs
Terraform (not needed by CI or the tests) and no AWS account; details in
[tests/fixtures/README.md](tests/fixtures/README.md#regenerating-the-scenario-13-plan):

```powershell
./scripts/generate-fixture-plan.ps1 -Variant vulnerable
./scripts/generate-fixture-plan.ps1 -Variant fixed
```
